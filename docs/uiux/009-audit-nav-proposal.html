✅ 設計重點

1Header 只剩 品牌 → 導航 → 🔗 + 👤：7 個元素 → 3 組，低頻動作（🌐☀️🚪）全收進帳號選單
2語言/主題是個人偏好、登出是帳號動作 — 全部掛在 👤 下語意才正確（⋮ 是 app 動作容器，放這些邏輯不對）
3🔄 重新整理是頁面動作 → 移到內容區 toolbar（Dashboard 搜尋列旁 / 稽核匯出列旁），動作就近發生在內容上
4👤 觸發器有 ▾ 箭頭 + hover/focus 樣式，明確表示「這是可點的選單，不是標籤」
5選單三區塊：資訊（admin）→ 偏好（主題/語言）→ 分隔線 → 危險動作（登出紅字），業界標準
6Mobile：帳號名隱藏、只剩 圓形頭像（切 📱 看）；選單從右緣展開不溢出

🎨 為什麼這樣分 核心原則

「選單裡裝什麼」決定「入口長什麼樣」：

  • 關於使用者的事（偏好/帳號）→ 👤 選單
  • 關於頁面的事（重新整理）→ 內容區 toolbar
  • 關於系統的事（連線狀態）→ 被動顯示、不可點

每個元素都問「它是誰的事」，Header 自然只剩 3 組。

♿ 無障礙與細節 標準

  • 真 <button> + dropdown（非 hover，touch 可用）
  • aria-haspopup / aria-expanded + Escape / 點外部關閉
  • ▾ 箭頭旋轉動畫、頭像用首字母（未來可換照片）
  • 登出在分隔線下方 + 紅字 = danger zone，防誤按
  • 選單項 icon + 文字（純 icon 難懂）

📱 Mobile 策略

  • 導航變 50/50 分割 tab，拇指友善
  • 帳號按鈕隱藏名字，只剩 圓形頭像（省空間）
  • 🔗 連線狀態保留（被動資訊，即時可看）
  • Header 高度只有 1 行，不再佔掉第一屏
🚫 已評估、未採用： ⋮ + 👤 雙選單（多一個圖示、兩種容器要學，零收益）｜ 登出常駐外露（每 session 只用一次的按鈕）｜ 👤 維持左側被動標籤（只是裝飾，失去入口功能）｜ 全部塞進 ⋮（語言/主題語意歸屬錯誤）

💡 加值（選配）：① Dashboard 統計列「今日操作」卡 → 點擊進稽核頁（mockup 已示範位置）；② 稽核頁有未讀新事件時在導航上顯示 紅點 badge（需後端支援上次瀏覽時間戳）；③ 選單資訊區未來可加 email / 角色（後端有資料時）。
