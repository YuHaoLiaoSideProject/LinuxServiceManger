# 003 — 部署安全性

**User Story：**
> As a 部署維運人員，
> I want 系統啟動時強制檢查必要的安全性環境變數已設定，且服務操作權限受服務鎖定機制約束，
> So that 不會因為忘記設定而使用預設密碼或預設 session 金鑰，導致系統暴露在攻擊風險中。

**驗收條件：**

**啟動階段安全性：**
1. **Given** 啟動時未設定 `SESSION_KEY` 環境變數，**When** 執行服務，**Then** 系統立即終止（Fatal）並輸出 `SESSION_KEY and ADMIN_PASS environment variables are required` 錯誤訊息
2. **Given** 啟動時未設定 `ADMIN_PASS` 環境變數，**When** 執行服務，**Then** 系統立即終止並輸出同上錯誤訊息
3. **Given** 啟動時已正確設定 `SESSION_KEY` 與 `ADMIN_PASS`，**When** 執行服務，**Then** 系統正常啟動，開始監聽指定 port

**服務鎖定機制：**
4. **Given** 系統正常啟動，**When** 查詢 `GET /api/v1/services`，**Then** 僅符合以下「全部條件」的服務標記為 unlocked（locked: false），前端可顯示 Start/Stop/Restart 操作按鈕：
   - 服務的 FragmentPath 位於 `/etc/systemd/system/` 目錄下
   - 服務名稱不以 `dbus-` 開頭
   - 服務的 UnitFileState 不是 static、masked 或 alias
5. **Given** 服務不滿足全數解鎖條件，**When** 查詢服務列表，**Then** 該服務標記為 locked: true，前端僅顯示 🔒 鎖定圖示，不顯示任何操作按鈕
6. **Given** 設定 `UNLOCKED_SERVICES` 環境變數（支援逗號分隔的清單與 glob 模式，如 `UNLOCKED_SERVICES=nginx,docker,my-*`），**When** 查詢服務列表，**Then** 符合該變數指定名稱或 glob 模式的服務強制標記為 unlocked，即使不符合第 4 條的預設解鎖規則
7. **Given** `UNLOCKED_SERVICES` 未設定或為空字串，**When** 查詢服務列表，**Then** 僅依第 4 條規則決定鎖定狀態

**資訊安全：**
8. **Given** 系統已正常啟動且 API 發生內部錯誤（如 D-Bus 連線失敗、systemctl 執行錯誤），**When** 前端呼叫 API，**Then** 回應僅包含 generic 錯誤訊息（如 `{"error": "failed to list services"}`、`{"error": "failed to start nginx"}`），不洩漏內部 stack trace、系統路徑或詳細錯誤原因
9. **Given** 未登入的使用者，**When** 呼叫任何受保護的 `/api/v1/` API，**Then** 回傳 401 JSON `{"error": "unauthorized"}`，不揭露任何系統資訊

**非功能性需求：**
- `SESSION_KEY` 建議使用 32 bytes 以上的隨機字串（可用 `openssl rand -base64 32` 產生）
- `ADMIN_PASS` 建議使用高強度密碼，避免與其他系統共用
- Session Cookie 設定為 HttpOnly，防止 XSS 竊取；閒置 30 分鐘後自動失效
- `ADMIN_USER` 環境變數可自訂管理員帳號名稱（若未設定，預設為 `admin`）
- 監聽 port 可透過 `PORT` 環境變數指定（若未設定，預設為 `8080`）

**優先級：** Must

**複雜度：** S
